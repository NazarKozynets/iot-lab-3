# Лабораторна робота №3 — IoT у Cisco Packet Tracer

Козинець Назарій Ігорович, КС-23, варіант 3.

`lab3.pkt` — модель для Cisco Packet Tracer 9.0.1. Усі вузли, включно з локальним сервером, підключені до WLAN `KNI_Lab3` із WPA2-PSK/AES. Навчальний ключ: `IoTLab3-2026`.

Сервер має статичну адресу `10.3.0.2/24`, виконує DNS та реєстрацію IoT. Єдина служба DHCP працює на маршрутизаторі `10.3.0.1`; DHCP на сервері вимкнено. Шлюз — `10.3.0.1`, пул DHCP — `10.3.0.100–149`, DNS-ім’я — `iot.home`.

Детектор утримує стан On протягом 10 секунд після останнього руху. Правила Conditions на сервері передають цей стан сирені. Гаражні двері керуються окремо з вебпанелі.

## Файли

- `motion-detector/main.js` — події руху й тайм-аут.
- `siren/main.js` — приймання команди, індикація й ручне перемикання.
- `network-plan.json` — адресація та правила.
- `verification/` — журнал перевірки у Packet Tracer.
- `tests/alarm.test.cjs` — окрема перевірка логіки з імітацією API.

## Перевірка моделі

Відкрити `lab3.pkt` у Packet Tracer. На планшеті відкрити `http://iot.home`; навчальний обліковий запис — `nazar` / `Lab3-IoT`. Імітація руху — Alt і рух миші над детектором. Після останньої події сирена вимикається через 10 секунд із невеликою затримкою мережевого обміну.

`npm test` перевіряє тайм-аут, повторний рух і обробку команд із підставним API. Це не заміна інтеграційній перевірці `.pkt`.

Для власного коду використано штатні API та індикацію smart-пристроїв Cisco Packet Tracer. Форматування — табуляція, ширина табуляції 4.
